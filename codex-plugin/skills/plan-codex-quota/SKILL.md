---
name: plan-codex-quota
description: Use Resetwise to plan when to use saved Codex reset cards, prefill a Resetwise link, or find another equally good plan in a follow-up.
---

Run `scripts/resetwise.mjs` with Node, resolving the path relative to this skill. All command inputs except `read` are JSON on stdin. By default the helper sends the planning inputs to `https://codex-resetwise.vercel.app`. For local development, point `RESETWISE_BASE_URL` at a running local Resetwise server.

1. Read the current account's usage with `read`. If the host already offers a read-only Codex usage tool, use it and pass its structured result to `normalize` instead. Use only the main Codex bucket. Treat a returned 300-minute window as active. For current personal Pro tiers, a missing 300-minute window means weekly-only. On other plans, ask when this is unclear. Use actual card expiry timestamps and ask about missing card details only when needed. Never redeem or buy a reset as part of planning.
2. Ask for the actual end of paid access if missing. For prepaid terms, use the paid term's expiry. Resolve dates in the user's local timezone and state any assumption about an unknown time. Pass `{ "usage": <normalized snapshot>, "settings": { "subscription": { "end": <epoch minutes> } } }` to `first` and ask for any other `missing` fields. Use 0 grace days and ask about the purchase channel only for channel-specific cancellation instructions. Preserve requests to skip renewal or use healthy hours. For continuous renewal only, pass `subscription.allowLapse: false`. For annual renewal, set `subscription.renewDays` to the actual duration of the next term, 365 or 366 days. Other optional settings include `subscription.channel`, `subscription.renew`, `subscription.billingDay`, `mode`, `hours` as two minutes-of-day values, `card.restart`, `resets` and `cards` as arrays of epoch minutes, `weekly` as `{remaining,end}`, and `short` as `null` or `{remaining,end,amount}`. Defaults include planning monthly renewal and a 16% five-hour cap.
3. If `first` or `more` recommends a `restart` renewal, confirm the user can let paid access lapse and is willing to rejoin the same plan, unless they already confirmed it. If they decline or cannot confirm, rerun `first` with the same usage and settings plus `subscription.allowLapse: false`. Reply with the total, baseline without cards, and `steps` in order. Include each card's time range and actual quota gain and the renewal time and kind. Link to `url` so the user can calculate and adjust on the website. Keep `context`, usage, and settings for later requests.
4. When the user asks for another plan, pass `{ "context": <latest context> }` to `more`. Add `action` using a card number or `"renewal"` and `direction` using `-1` for earlier or `1` for later when requested. Present the returned plan in the same format. `recalculated` means the previous plan included a grace period and this is the new first plan. An `exhausted` result means that search has no unshown equal-quota alternative. For a temporary failure, keep the existing context for a retry.
