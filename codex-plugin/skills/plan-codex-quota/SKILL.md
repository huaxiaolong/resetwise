---
name: plan-codex-quota
description: Use Resetwise to plan when to use saved Codex reset cards, prefill a Resetwise link, or find another equally good plan in a follow-up.
---

Run `scripts/resetwise.mjs` with Node, resolving the path relative to this skill. All command inputs except `read` are JSON on stdin. The helper uses the local Resetwise backend by default. `RESETWISE_BASE_URL` can point to the Resetwise Vercel site once the prefill-enabled webpage is deployed there.

1. Read the current account's usage with `read`. If the host already offers a read-only Codex usage tool, use it and pass its structured result to `normalize` instead. Use only the main Codex bucket. Treat a returned 300-minute window as active. For current personal Pro tiers, a missing 300-minute window means weekly-only. On other plans, ask when this is unclear. Use actual card expiry timestamps and ask about missing card details only when needed. Never redeem or buy a reset as part of planning.
2. Pass `{ "usage": <normalized snapshot>, "settings": { "subscription": { "end": <epoch minutes> } } }` to `first`. Ask for any `missing` fields before presenting a plan. Use 0 grace days for Skill calculations. Include `subscription.channel` when the user has already given it. Resolve dates in the user's local timezone and preserve an explicit request to skip renewal, use healthy hours, or keep the existing refresh schedule. Defaults include planning renewal and a 16% five-hour cap. Optional settings include `subscription.renew`, `subscription.renewDays`, `subscription.billingDay`, `mode`, `hours` as two minutes-of-day values, `card.restart`, `resets` and `cards` as arrays of epoch minutes, `weekly` as `{remaining,end}`, and `short` as `null` or `{remaining,end,amount}`.
3. Reply with the returned total, the baseline quota without using cards, and `steps` in their given order. For each card, include its time range and actual quota gain. For renewal, include its time and kind. Link to `url` so the user can verify the prefilled form, calculate, and adjust on the website. Keep the returned `context` in the conversation for later requests. It is for the helper, not for display.
4. When the user asks for another plan, pass `{ "context": <latest context> }` to `more`. Add `action` using a card number or `"renewal"` and `direction` using `-1` for earlier or `1` for later when requested. Present the returned plan in the same format. `recalculated` means the previous plan included a grace period and this is the new first plan. An `exhausted` result means that search has no unshown equal-quota alternative.
